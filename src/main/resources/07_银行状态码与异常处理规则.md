# 银行状态码与异常处理规则

## 1. 适用范围

本文档适用于财资管理系统中的银企直连交易状态处理、异常处理、重复提交控制、人工核查等场景。

## 2. 通用状态映射

| 银行返回状态 | 系统状态 | 是否最终状态 | 说明 |
|---|---|---|---|
| SUCCESS | 成功 | 是 | 银行明确返回交易成功 |
| FAILED | 失败 | 是 | 银行明确返回交易失败 |
| ACCEPTED | 银行处理中 | 否 | 银行已受理 |
| PROCESSING | 银行处理中 | 否 | 银行正在处理 |
| PENDING_CLEARING | 银行处理中 | 否 | 跨行交易等待清算 |
| NEED_AUTH | 待授权 | 否 | 需要企业授权确认 |
| TIMEOUT | 银行处理中 | 否 | 接口超时，不能判定失败 |
| UNKNOWN | 待核查 | 否 | 银行状态未知 |
| NOT_FOUND | 银行处理中 | 否 | 可能存在银行同步延迟 |

## 3. 成功状态处理

银行明确返回成功时，系统需要执行以下动作：

1. 更新交易状态为成功。
2. 保存银行流水号。
3. 更新付款结果。
4. 释放占用的支付额度。
5. 允许下载电子回单。
6. 发送付款成功通知。
7. 记录银行响应日志。

## 4. 失败状态处理

银行明确返回失败时，系统需要执行以下动作：

1. 更新交易状态为失败。
2. 保存失败原因。
3. 释放占用的支付额度。
4. 通知经办人。
5. 允许经办人基于失败原因重新提交。
6. 禁止下载电子回单。
7. 记录失败日志。

## 5. 银行处理中状态处理

以下状态均应视为银行处理中：

- ACCEPTED
- PROCESSING
- PENDING_CLEARING
- TIMEOUT
- 已受理
- 待清算

处理规则：

- 不允许用户重复提交同一笔交易。
- 不允许下载电子回单。
- 系统需要定时查询最终状态。
- 超过最大查询次数后，进入人工核查队列。
- 人工核查前，不得将交易改为成功或失败。

## 6. 超时处理规则

接口超时不代表交易失败。

如果调用银行转账接口超时，系统应：

1. 检查是否已生成本地交易流水号。
2. 如果银行流水号已返回，则使用银行流水号查询状态。
3. 如果银行流水号未返回，则使用请求流水号或企业流水号查询。
4. 如果无法查询到交易，进入人工核查队列。
5. 不允许立即重新发起相同付款，避免重复付款。

## 7. 重复提交控制

系统需要通过以下字段防止重复提交：

- 企业付款流水号
- 业务单据号
- 付款账号
- 收款账号
- 付款金额
- 付款用途
- 请求时间窗口

规则：

- 同一业务单据号不得重复发送银行。
- 银行处理中状态不得重复发送。
- 失败后重新提交必须生成新的发送记录。
- 成功交易不得重新发送。
- 用户重复点击提交按钮时，系统应通过幂等键拦截。

## 8. 人工核查规则

以下情况需要进入人工核查：

- 银行状态长时间未知。
- 银行返回 UNKNOWN。
- 接口超时且无法确认银行是否受理。
- 本地状态与银行状态不一致。
- 回单下载成功但交易状态不是成功。
- 银行流水号缺失。
- 同一业务单据出现多条银行发送记录。

人工核查处理要求：

1. 核查人员查看银行流水。
2. 核对付款账号、收款账号、金额、交易日期。
3. 根据银行最终结果修正系统状态。
4. 操作过程必须记录审计日志。
5. 状态修正后通知经办人。

## 9. 常见问答

### 问：银行接口超时了，系统能不能直接重发？

答：不能。接口超时不代表银行没有处理该笔交易，直接重发可能导致重复付款。系统应先查询交易状态或进入人工核查。

### 问：银行处理中可以下载回单吗？

答：不能。只有银行明确返回成功，并且银行已生成电子回单后，才允许下载回单。

### 问：UNKNOWN 状态应该怎么处理？

答：UNKNOWN 状态应进入人工核查队列，不能直接标记为成功或失败。
